# AWS Agent Core - How It Actually Works

## KEY DISCOVERY: Agent Core is NOT Bedrock Agents!

Agent Core is a completely different service from traditional Bedrock Agents.

## The Real Agent Core Architecture

### 1. Python Package: `bedrock-agentcore`

- Install via: `pip install bedrock-agentcore`
- NOT deployed via AWS CLI commands
- Uses a special CLI tool: `agentcore`

### 2. Development Workflow (Pure Python - NO third-party frameworks)

```bash
# Step 1: Write your agent in Python with special decorator
from bedrock_agentcore.runtime import BedrockAgentCoreApp
import boto3

app = BedrockAgentCoreApp()
bedrock = boto3.client('bedrock-runtime', region_name='us-east-1')

@app.entrypoint
def agent_invocation(payload, context):
    # Pure Python logic
    prompt = payload.get("prompt", "")

    # Call Bedrock directly with boto3
    response = bedrock.converse(
        modelId="us.amazon.nova-pro-v1:0",
        messages=[{"role": "user", "content": [{"text": prompt}]}]
    )

    answer = response['output']['message']['content'][0]['text']
    return {"answer": answer}

# Step 2: Configure the agent
agentcore configure -e your_agent.py

# This generates: bedrock_agentcore.yaml

# Step 3: Deploy to Agent Core
agentcore launch

# Step 4: Invoke the deployed agent
agentcore invoke '{"prompt": "your question"}'
```

### 3. Key Components

**BedrockAgentCoreApp**

- Main application class
- Defines entrypoints with `@app.entrypoint` decorator
- Handles payload and context from Agent Core

**Entrypoint Function**

- Receives `payload` (user input) and `context` (runtime info)
- Returns a dictionary response
- This is what Agent Core Runtime calls

**Configuration File: bedrock_agentcore.yaml**

- Generated by `agentcore configure`
- Defines agent settings
- Used during deployment

### 4. Agent Core Features

**Runtime**

- Hosts your Python agent
- Manages execution and scaling
- Handles invocations

**Gateway**

- Exposes agents as API endpoints
- Custom domains
- (Configure after deployment)

**Identity**

- Cognito integration
- Authentication/authorization
- (Configure after deployment)

**Memory** (Optional - can add later)

- Persistent conversation history
- Session-based tracking

### 5. What We Were Doing Wrong

❌ **Wrong:** Using `aws bedrock-agent create-agent` CLI commands
❌ **Wrong:** Trying to deploy Strands agents directly
❌ **Wrong:** Looking for Agent Core in Bedrock Agents console
❌ **Wrong:** Using LangChain/LangGraph (unnecessary complexity)

✅ **Right:** Install `bedrock-agentcore` Python package
✅ **Right:** Use `agentcore` CLI tool
✅ **Right:** Write agents with `@app.entrypoint` decorator
✅ **Right:** Use pure Python + boto3 for simplicity

```

└── data/                      # Your data files (optional)
```

### 8. Key Differences from Strands

**Strands:**

- Local development library
- Calls Bedrock APIs directly
- You manage everything

**Agent Core:**

- Managed service
- Deploy to AWS infrastructure
- AWS handles scaling and hosting
- Use `agentcore` CLI for deployment
